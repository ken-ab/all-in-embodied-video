# 反馈与学习

每期的返修和发布后的数据都要回到下一期。两条回路分开记账，在下期开工时汇合：

| 回路 | 学什么 | 证据 | 记在哪 |
|---|---|---|---|
| 制作回路 | 创作者认可的成片该长什么样：封面、上半屏、字幕、术语、剪点 | 创作者的返修 | 本期 `返修记录.md` → 项目 `制作规则.md` |
| 内容回路 | 什么选题、开头和讲法带来播放与完播 | 发布后的平台数据 | cheat-on-content 的 `predictions/`、`rubric-memo.md`、`script_patterns.md` |

内容回路交给本 Skill 内置的 `cheat/` 模块（合并自 [cheat-on-content](https://github.com/XBuilderLAB/cheat-on-content)，下称 cheat），制作流程不另做数据判断。cheat 的每个子流程都是 `cheat/flows/cheat-*/FLOW.md`，触发词和对应文件见 SKILL.md「内置 cheat 模块」。Dot 负责按时间触发。抖音是唯一的校准平台；小红书和视频号的数据作附加报告，供复盘参考，不进入 cheat 的校准。

## 1. 前提：项目根同时是 cheat 内容项目

- 项目根有 `.cheat-state.json`。没有时先说「初始化 cheat-on-content」：内容形态选教程类（cheat 的 `starter-rubrics/tutorial-builder-zero.md`），复盘数据来源选 adapter，平台选抖音。
- 三个平台的登录态保存在项目根：抖音 `.auth/`、小红书 `.auth-xhs/`、视频号 `.auth-wechat-channels/`。首次登录按 README「数据抓取准备」扫码，登录态只留在本机。
- `<CHEAT_DIR>` 指本 Skill 目录下的 `cheat/`。数据抓取脚本在 `<CHEAT_DIR>/adapters/perf-data/`。
- 初始化时 cheat 会问是否安装 hook。hook 只在 Claude Code 里生效；在 Codex 里运行时回答不装。预测是否被改动由 `<CHEAT_DIR>/tools/prediction_lock.py` 检查，两种环境都适用。
- cheat 的 `rubric_notes.md` 是盲打分白名单，只写抽象规则。本 Skill 不往里面写任何作品名、数据、评论或链接。
- 教程类评分规则在冷启动期误差约 ±50%。跑满 5 期完整循环（预测 → 发布 → 72 小时复盘）后才可能提出第一次评分规则升级，前几期预测不准属于正常情况。

## 2. 开工时先读规则

整理笔记、给关键词提纲之前，依次读：

1. 项目根 `待确认.md`。有条目时先逐条列给创作者，按回复处理（见第 7 节），再开始本期。
2. 项目 `制作规则.md` 的「已确认」段。本期全程遵守。
3. cheat 的 `script_patterns.md` 正式 pattern 和 `audience.md`。用于选关键词顺序、开头问题和举例；「待验证」的 pattern 只作提示。
4. 最近一到两期的 72 小时复盘摘要（cheat 预测文件的 `## 复盘` 段）。

提纲里用到的规则或 pattern，在任务说明里记一行出处，方便复盘时判断它有没有起作用。

## 3. 返修：每条反馈记成一个单元

创作者的每条返修意见，以及验收中发现的问题，都写进本期 `返修记录.md`（模板见 `templates/返修记录.template.md`）：

```text
单元   上半屏 · 第 2 段链路图
类别   画面/链路图
判定   不通过
原因   「采集 → 训练 → 推理」少了推理一步
证据   成片 01:12–01:20
范围   只改这张图和它的出现时间，不动字幕和其他图卡
```

- **只退这个单元。** 其他已验收的部分不重做。改动引起切点或时长变化时，按 `keep.json` 同步字幕、图卡和预览，并在记录里写明连带改动。
- **范围写清楚。** 修复不越出范围；顺手发现的其他问题另开一个单元。
- **每个单元最多修 3 次。** 第 3 次仍不通过，标「卡住」，写清原因和需要创作者决定的事（例如需要补录），先做其他单元。
- **类别从固定列表里选**，方便跨期统计：`口播/剪点`、`口播/补录`、`字幕/术语`、`字幕/断句`、`画面/实拍图`、`画面/链路图`、`画面/解释字`、`封面/构图`、`封面/文字`、`文案/标题`、`文案/正文`、`声音`、`其他`。确实都不合适时用 `其他` 并在原因里说明。

## 4. 定稿前用 cheat 打一次分

口播稿整理完、剪辑定稿前，说「打分这篇 <本期口播稿.md 路径>」。cheat-score 只打分，不写文件。

- 低于 3 分的维度，按它指出的具体句子或段落各开一个返修单元，类别用对应的 `口播/...` 或 `画面/...`。例如开头钩子低分，给出可直接念的补录开头和替换范围。
- 只打这一轮。不为了提高分数改动创作者的观点和用词；创作者不采纳的建议，在单元里记「创作者保留原样」后关闭。

## 5. 发布前锁定抖音预测

成片和口播稿都定稿、还没有任何一个平台发布时：

1. 说「启动预测 <本期口播稿.md 路径>」，平台填抖音。稿子不在 cheat 的 `scripts/` 下时，cheat 会问是否复制过去并计算 id，回答同意。cheat 列出各维度打分后，创作者可以挑刺修改，确认后才在 `predictions/` 落盘，随即运行 `prediction_lock.py lock` 锁定。预测写完不能改；72 小时复盘开始前会先校验锁定，对不上就停止复盘。
2. 说「拍了 <cheat 给出的 scripts 路径>」。cheat 问实际拍摄稿是否一致时回答一致；问是否需要 v2 预测时回答不需要。
3. 在任务说明里记下预测文件和 cheat 作品文件夹（`videos/...`）的路径。

已经有平台发布、或已经看过数据时，不再补写预测，在任务说明里记「本期无预测」。这一期仍可做附加数据复盘，但不进入校准。

## 6. 发布后登记，交给 Dot

抖音实际发表后，说「已发布 <抖音作品链接>」。cheat 记下 aweme_id 和发布时间，并把本期加入待复盘列表。小红书和视频号不在 cheat 里登记（cheat 的一份预测只对应一个平台），它们的作品 ID 写进 Dot 交接单。

交接单按 `templates/Dot交接单.template.md` 填写，随归档材料一起交给 Dot。各平台的定时任务和执行规则见 [归档与复盘](归档与复盘.md)。

## 7. 待确认队列

Dot 在无人值守时执行，凡是需要创作者回答的事都不当场等待，写进项目根 `待确认.md`，下期开工时一次处理：

| 条目 | 来源 | 创作者回「要」之后 |
|---|---|---|
| 写法 pattern 候选 | cheat 72 小时复盘提出 | 按 cheat 的 `script_patterns.template.md` 格式追加到 `script_patterns.md`，单样本的标「待验证」 |
| 评分规则升级提议 | cheat 复盘检测到系统性偏差 | 另起一步说「升级 rubric」，按 cheat 的升级流程执行，不在开工流程里顺带完成 |
| 热门评论待补 | 适配器没抓到评论 | 创作者粘贴热门评论后，说「复盘 <预测文件>」选择补充，按 cheat 追加 |
| 制作规则候选 | 本节下方的升级条件 | 写进 `制作规则.md`「已确认」段 |

创作者回「不要」的条目直接删掉。没回复的条目留到下次。

## 8. 制作规则怎么升级

- **候选条件**：同一类别的返修在两期或以上出现，且指向同一个方向（例如两期都嫌封面主标题太长）。开工或交付时检查本期和往期 `返修记录.md`，满足条件就写进 `待确认.md`，附上两期的单元原文。
- **升级**：创作者确认后，写进 `制作规则.md` 的「已确认」段，一条一行，注明来源期数。
- **推翻和合并**：新的返修与某条已确认规则相反，或规则已经并入本 Skill 的正式流程，就删掉那一条，不保留历史版本；需要查历史时看 git 记录。
- **数据结论不进制作规则。** 播放、完播和互动带来的结论只走 cheat 的回路，避免两套规则互相打架。
