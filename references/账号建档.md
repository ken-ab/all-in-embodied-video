# 账号建档

预测和复盘要有参照：你自己的账号现在是什么水平，你想做成哪个账号的样子。建档就是把这两件事告诉 cheat。它执行内置的 [cheat-init](../cheat/flows/cheat-init/FLOW.md) 和 [cheat-learn-from](../cheat/flows/cheat-learn-from/FLOW.md)，问题按 All In 具身的情况预先填好，只问真正需要创作者回答的部分。

## 什么时候做

- **项目根没有 `.cheat-state.json`**：开工时先建档，建完再开始本期。用户说「初始化 cheat-on-content」或「建档」时也从这里开始。
- **`benchmark_status` 是 `pending`**：每期开工提醒一次「对标账号还没导入」，用户同意就从第 3 节继续。
- **想换对标或加对标**：用户说「找对标」「学这个账号」，直接走第 3 节，选追加或替换。
- 已建档的项目再次说「初始化」时，cheat-init 会先确认是否覆盖，不会自动清空。

## 怎么问

- **一次只问一个问题**，等回答再问下一个。能从项目里查到的，先查出来请用户确认，不让用户重新报一遍。
- 用户说「先跳过」的项目，按 cheat 的规则标成待补（例如 `benchmark_status: pending`），不卡住本期制作。
- 建档的回答写进 cheat 的状态文件和对应文件，同时在项目根 `账号档案.md` 留一份人能读的摘要（模板见 `templates/账号档案.template.md`）。

## 1. 预设，只请用户确认

以下 cheat-init 的问题不再逐条问，一次列出来请用户确认或改：

| cheat-init 问题 | 预设 | 写入 |
|---|---|---|
| Q1 内容形态 | 教程 / 知识讲解（e） | `content_form: "tutorial-builder"`，评分规则用 `starter-rubrics/tutorial-builder-zero.md` |
| Q3 数据回收 | adapter 自动抓 | `data_collection: "adapter"` |
| Q4 候选选题 | 没有，选题来自每期笔记 | `pool_status: "none"` |
| Q5 hook | Codex 里不装；Claude Code 里装 | `hooks_installed`。预测锁定由 `cheat/tools/prediction_lock.py` 负责，两种环境都生效 |

cheat-init 的开场文案可以省略，但这两句期望必须说：前 5 期预测误差大约 ±50%，对标账号越早导入越好。

## 2. 你的账号

按顺序问：

1. **账号**：抖音、小红书、视频号的账号名或主页链接。抖音必填，它是唯一的校准平台。
2. **定位和受众**：一句话说清这个系列讲什么、给谁看、看完带走什么。写进 `账号档案.md`，开工写提纲时用。
3. **典型时长**：先从往期成片或发布记录查出常见时长，请用户确认，按 cheat-init Q1.5 换算写入 `typical_duration_seconds`。
4. **发布节奏**：先从发布记录里的 Day N 和发布日期推算，请用户确认，写入 `target_publish_cadence_days`。
5. **历史作品导入**（cheat-init Q2 = 发过，Q2.1 = 抖音）：
   - 确认抖音已扫码登录（README「数据抓取准备」）。运行 `python <CHEAT_DIR>/adapters/perf-data/douyin-session/review.py list` 列出最近 20 条，请用户确认导入多少条，建议 10 到 20 条。
   - 逐条用 `<CHEAT_DIR>/adapters/perf-data/douyin-session/run.sh <aweme_id> <videos 下该条的文件夹>` 抓数据，一次一条。
   - **稿子直接用往期的 `口播稿.md`。** 按发布记录里的作品链接、标题或 Day N 对上本项目对应一期的制作目录；对不上或没有口播稿的，标 `script_lost`，不请用户回忆原稿。
   - 按 cheat-init Phase 3.5 写成「反推的历史复盘」（标明不是盲预测，不计入校准样本），并取播放量中位数写入 `baseline_plays`。之后的预测档位按这个基准划分。
   - 小红书和视频号的历史不导入校准，可在 `账号档案.md` 里记一行近期大致水平。

## 3. 对标账号

执行 cheat-learn-from。All In 具身的默认做法：

1. **选账号**：请用户给 1 到 3 个想做成那样的账号，最好是同领域（具身智能、机器人、AI 技术讲解）的口播类账号。先导入一个，其他的以后追加。
2. **选样本**：每个账号 5 到 10 条，高、中、低表现都要有，只挑爆款学不到差别。少于 3 条不导入。
3. **稿子来源**：默认请用户粘贴文案（可用「轻抖」一类小程序从视频链接提取）。用户手上有视频文件时，放进 `samples/<账号名>/`，用 cheat 的 whisper 转录（见 `cheat/adapters/script-extraction/whisper/README.md`）。
4. **数据来源**：对标账号不是你的账号，后台抓不到，**数据手填**：播放、点赞、评论、转发，有收藏也填。
5. **你的印象**：每条问一句「你觉得它为什么好或不好」。这是 cheat 拆 pattern 的重要输入，不能省。
6. cheat 拆出 pattern 和评分信号，用户过目确认后，写入 `benchmark.md`、`script_patterns.md` 和 `rubric_notes.md`，状态改为 `benchmark_status: imported`。

## 4. 建档完成后

给用户一段摘要：账号和平台、基准播放、导入了几条历史、对标账号和样本数、当前预测置信等级、还有哪些待补。然后回到本期制作的第 1 步。

之后每期会用到建档结果：

- **开工写提纲**：读 `账号档案.md` 的定位和受众、`benchmark.md` 和 `script_patterns.md`。
- **打分和预测**：cheat 按教程类评分规则和对标信号打分，按 `baseline_plays` 划预测档位。
- **受众画像**：攒够几期复盘评论后，用户说「构造受众画像」，由 cheat-persona 从真实评论生成 `audience.md`。
- **每 5 期**：开工时检查一次对标是否还合适，账号定位变了就追加或替换对标。
