# All In 具身｜从整理资料到发布（正式版 v1.4.0）

更新于 2026-11-05。每期从创作者提供的笔记开始。创作者先看整理后的 HTML，再围绕关键词自由录制。拿到实录后整理口播稿并完成剪辑。Mac 和 Windows 可从实际完成的阶段继续。返修和发布后数据怎样回到下一期，见[反馈与学习](反馈与学习.md)。

## 1. 整理学习笔记，给出口播关键词

项目还没建档时，先按[账号建档](账号建档.md)建档。开工前按[反馈与学习](反馈与学习.md)第 2 节读规则：先处理 `待确认.md`，再读 `账号档案.md`、`制作规则.md` 已确认段、cheat 的 `benchmark.md`、`script_patterns.md` 与 `audience.md`，以及最近的 72 小时复盘。

收到当期资料后，建本期制作目录。先从上一期已确认的制作或发布记录查 `All In 具身｜Day N`，顺延本期编号。多个平台发同一期只算一个 Day。遇到合并期、补发、跳号或记录冲突，先核对本期已知安排；只有确实无法确定时再向用户确认。课件编号、Mac 工程编号和文件日期用于找资料。

以用户提供的笔记为底稿，按主题、问题和概念关系组织章节。把该放的实拍图、原始截图和真实图表插在对应解释旁，附图注与出处链接。需要说明结构、先后或因果时补关系图、链路图或时间线，并标明示意。适合对照的内容用表格，公式说明符号和成立条件。资料支持时加实际案例或小练习，答案和解析另列。技术事实和数字以来源为准，让整份笔记脱离视频也能读懂。

| 版本 | 制作方式 | 何时展示 |
|---|---|---|
| `学习笔记.md` | 保存完整章节、图注、来源链接和可用的图文件，作为更新底稿。 | 首轮保存到本期目录，审看入口用 HTML。 |
| 独立 `学习笔记.html` | 从同一版 MD 渲染，保持章节、内容、图片和链接一致。把本期图片、图形和样式放进独立文件，检查手机阅读。 | 笔记整理好时给用户看的唯一笔记版本。 |
| 抖音或小红书图文 | 用户准备发布笔记时，从已确认的笔记选封面、拆分要点、配实图或关系图，输出按序排列的图片和发布文案。每页围绕一个信息点，保留必要图注、来源与技术条件，按目标平台当前上传页核对顺序、裁切和手机可读性。 | 等用户提出准备发布笔记，再制作并展示目标平台的图文版。 |

首轮交付时，聊天文字只列本期关键词和短提纲。按短视频的内容密度、用户自然语速和已有时长要求选重点，把关键问题、概念顺序和适合顺手举的例子列出来，让用户围绕这些重点按自己的话录一遍。完整背景和细节留在 HTML。

已有笔记样例时，沿用创作者认可的章节和排版风格。分发已经确认的笔记原文时，保留其内容、图表和顺序。

## 2. 从笔记选上半屏画面

以学习笔记和用户点出的重点为取材依据。优先用笔记里已有的真实图片、图卡和链路图。需要为讲解补画新图时，尽量把同一张图也放入笔记对应章节，方便用户照着笔记录和读者对照。录制前可以选好图和解释字，收到实录后再按真正讲到的位置安排出现和停留时间。

- 实物和场景用当期照片、截图或素材片段。看结构用局部放大、箭头、颜色和简短标注。
- 概念关系或流程用可读的链路图。顺着讲解逐步亮起节点和箭头，画面推进跟着实际口播。比如讲「采集 → 训练 → 推理」时逐步展示三段，分别用一句话标出各段做的事。
- 文字只放帮助理解的术语、结论和解释。对比、时间关系或示例适合用图片、对比卡或简短动画。需要展示原题时，按本期要求保留原题和选项，给阅读时间，再接答案与解析。
- 真人是主体，图和解释字在需要时出现。按手机构图检查字号、停留时间及与真人、字幕的遮挡。技术插图和生成图的内容要对得上资料，示意画面应有相应标注。

## 3. 收到录制文件，做完整剪辑

用仓库内的粗剪流程整理素材、核对重讲和静音候选，并把选中的段落渲染到一条统一时间线。[口播粗剪](口播粗剪.md)

更新本期任务说明，登记笔记、关键词、上半屏选图、收到的口播和录屏、补录、封面方向及当前阶段，并从 `templates/返修记录.template.md` 建本期 `返修记录.md`。普通视频文件可先按原片检查。来自 Mac 的 ZIP 通常已有剪辑进度，打开清单核对是否包含工程、已剪 MP4、字幕、图卡或仅有原素材，再从对应阶段继续。

1. **从实录整理口播稿，再据此剪口播。** 听用户实际说了什么，按他想表达的主线整理 `口播稿.md`，保留观点、用词、叙述顺序与个人语气。可清掉赘词、重复和明显口误，疑似事实错误或影响意思的改动标出原句和时间点。口播稿以实录为主，关键词用于定位。确认主讲、补录、收尾及素材顺序，通过试听确定剪点，保留原速、完整发音和有效停顿。口播稿整理完后，按[反馈与学习](反馈与学习.md)第 4 节用 cheat 打一次分，低分维度各开一个返修单元。
2. **对照学习笔记补画面。** 每段回看相关笔记，选观众听口播时最需要看到的示意、例子、链路、关键名词或对比。笔记中的补充知识落到对应句子，字幕仍以实际口播为准。开场、关键解释和段落过渡分别检查有无需要画面辅助的地方，再把合适的图片、贴图、标注、动效或转场实际放进时间线。说明每个重点画面在帮助观众看懂什么。
3. **主动处理补录。** 发现某处口误影响结论、跳过关键一步或衔接断开，给出原片或成片时间、原因、可直接念的补录短稿及插入或替换范围。可继续剪的段落先做。用户补录或指定结构后，在同一版时间线接入，并复查上下句。
4. **完成字幕和声音。** 用粗剪后的时间线生成或复用字幕，听原声核对术语、数字、单位、断句和同步。需要时降噪并统一人声音量，复听尾音和切点。配乐和声效按本期要求；技术长讲解默认无贯穿配乐。明确要求去配乐时保留已验收的人声处理。
5. **首遍按可发表质量剪。** 粗剪是内部步骤，第一遍对外可看的中稿已包含应有的声音、字幕、辅助画面和封面。通常一到两遍，用户觉得可以就按授权发布。返修时每条意见记成 `返修记录.md` 里的一个单元，写清证据和范围，只退这个单元；每个单元最多修 3 次，仍不通过就标「卡住」并说明需要创作者决定的事。切点或时长变化时同步更新字幕、章节、图卡和预览。每次交出的版本都按定稿验收标准做。

### 剪映的素材也要实际用

剪映用于本期剪辑时，按画面方案查看软件里实际可用的贴纸、图形、标题样式、转场和关键帧动画。选适合讲解的素材放入对应片段，例如用箭头标结构、用高亮逐步展开链路、在章节切换时用简洁转场。具体效果以实际可用和手机可读为准。优先把有用的图做出来，复杂技术图可以自制或生图后导入剪映。交付说明简记实际用了什么、用在哪，区分剪映内置素材、自制图和本地合成。

### Mac 和 Windows 从同一阶段继续

Mac 作为录制文件上传较快时的制作入口，走本 Skill 的同一套步骤。把 `任务说明.md`、两种笔记文件、关键词、上半屏资产，以及已有的实录口播稿、工程、素材路径、最新 MP4、字幕、封面和待补清单随当前 ZIP 交接。Windows 先查已完成阶段和最新版本，再继续剪辑、返修、验收或发布。工程可用时在副本上重连并抽查切点。缺少原片或某条轨道时，记录可修改范围，保留原工程和已验收版本。

## 4. 自动生成标题、文案和封面

- 按本期资料、实际内容和已核实的系列编号，主动生成标题、平台文案和封面。默认使用 `All In 具身｜Day N` 的系列标识，并把主题写清楚。分别交 **发布标题、正文首行、封面主标题、封面小字**，对应位置独立修改。平台有字符限制时记录该平台实际填法。
- 按[封面制作](封面制作.md)和已确认封面参考延续既有风格。系列标识较小，主题醒目，小字补充知识点。按这期内容选构图、颜色、贴图和表情。保留本人身份和真实摄影感，优先自然表情，按当期授权调整。
- 每期出十张独立 PNG 和总览。用户选定一张主封面后，助手从余下九张选三张小红书 PK 备选，连同主封面共四张。记录顺序与实际上传的封面。抖音和小红书沿用本项目 3:4 封面，视频号按当前封面入口适配，逐平台核对真实裁切。

## 5. 手机预览里验收，整包交付

1. 导出实际 MP4，核对解码、画幅、音画同步、补录衔接、长字幕、技术图的可读性和收尾。剪映工程保存后重开，确认原声、字幕、辅助画面、关键设置和实际素材可用。只能提供底片、字幕及时间线时，标为可编辑素材包。
2. 用[手机预览工具](手机预览.md)生成抖音、小红书、视频号三个手机模拟视图。**这就是默认审看和验收入口。** 在预览里验证能播放同一版 MP4，标题、文案和封面与本期交付对应，首屏、字幕、上半屏插图和结尾没有被平台界面遮挡。返修后更新同一入口或清楚标新版。
3. 默认交付 **完整 ZIP＋选定封面＋三平台手机预览＋四个文案字段**。ZIP 放最终 MP4、从实录整理的口播稿、学习笔记 MD 和 HTML、实际字幕与画面资产、封面及 PK、文案和交付清单。附已验证的剪映工程及其所需素材，或注明实际可编辑的素材包和重连条件。交付清单标明唯一可用的定稿、版本和工程状态，校验 ZIP 可打开。图文版按笔记发布阶段单独交付。
4. 定稿交付后、任何平台发布之前，按[反馈与学习](反馈与学习.md)第 5 节锁定抖音预测：「启动预测 <口播稿路径>」，再「拍了 <scripts 路径>」。已有平台发布时不补写，记「本期无预测」。

## 6. 上传与发布

| 时机 | 执行规则 |
|---|---|
| 收到「传」 | 按当期平台和时间上传并提交发布。用户说「只上传」「存草稿」或指定定时，就按其明确要求。使用创作者明确指定的抖音、小红书或视频号账号。 |
| 开始和重传 | 先查作品管理及保留编辑页，核对账号、标题、编号、版本、时长和时间。已有审核、定时或已发表记录时沿原作处理。同一视频已传完时从该表单继续。上传有进度就保留页面。遇到明确失败时最多采用两条有实质区别的处理路径。 |
| 提交前 | 查主表单里的视频和封面、文案、公开状态、合集和小红书 PK。定时核对完整日期、北京时间和所选模式。发布按钮受布局遮挡时用当前可见控件或正常键盘操作。明确的工具限制出现时，保留原页，请用户完成最后一步。 |
| 提交后 | 查作品列表，记录后台真实状态、时间、作品标识和凭证。上传完成、已提交审核、已定时和已发表分开记录。已有记录需要改文案或时间时打开原帖编辑，核对保存结果。抖音实际发表后说「已发布 <抖音作品链接>」，在 cheat 里登记。 |

## 7. 发布归档和检查交给 Dot

剪辑和发布阶段负责留下交接所需的信息。**实际发表后按 `templates/Dot交接单.template.md` 填好交接单，连同成片、实际使用的封面、发布凭证和归档位置交给 Dot。** 交接单里写明 cheat 预测文件、作品文件夹和三个平台的作品 ID。归档和发布后检查由 Dot 执行。Dot 入口或执行环境尚不可用时，登记待交接并保留材料；剪辑会话不代跑检查。

- **抖音是唯一的校准平台。** 24 小时做快照，72 小时由 cheat-retro 正式复盘。
- **小红书** 24 小时和 72 小时各做一次快照，作附加报告。
- **视频号** 只在 72 小时做一次快照，作附加报告；不做 24 小时检查，不轮询，不补查旧积压。
- 各阶段以实际发表时间为起点，单次执行。草稿、定时和审核中先记状态。沿用队列去重、只读、统计截止、缺项、延迟和登录挂起规则。复盘中需要创作者回答的事写进 `待确认.md`，下期开工处理。到期补查也交给 Dot，不恢复轮询。详见 [归档与复盘](归档与复盘.md)。
